# Шарага — приложение и синхронизация

Личный учебный органайзер для группы Б-ОРМ-41 (КГУ).

Приложение: **https://storytailer.github.io/sharaga/**

## Как это работает

```
телефон ──» облако ──» ноутбук        ноутбук ──» облако ──» телефон
(писать ДЗ)   (Cloudflare)  (ты пишешь тут)   (готовые)      (появляется у пар)
```

Три части: приложение на iPhone, облако (Cloudflare Worker) и синхронизатор
на ноутбуке. Всё ходит само, нажимать кнопки синхронизации не нужно.

## Главный принцип: задание живёт до следующей пары

Задание пишется у той пары, **на которой его задали**, и сдаётся на
**следующей паре по этому же предмету**. Пример: задали в понедельник —
срок в среду.

Раньше записи хранились по названию предмета, и это всё ломало: два задания
одного предмета затирали друг друга, а в облако уходило `{"Социология":"эссе"}`
без даты — по такому заданию невозможно понять, к какой паре оно относится.

Сейчас запись ключуется парой `дата|время` и сама помнит:
- `dz` / `dzAt` — задание и когда его записали;
- `ready` / `readyAt` — готовое решение и когда его положили;
- `dueD` / `dueT` — на какой паре сдавать.

Во вкладке «Задания» есть список: предмет, срок сдачи, текст задания и
готового, пометка «просрочено». Бейдж «✎ ДЗ» висит на паре **сдачи**,
а «✎ задали» — на паре, где задание выдали.

## Слияние без потерь

Поля сливаются по меткам времени: свежее поле побеждает, а не «облако
перезаписало всё». Поэтому:
- готовое решение с ноутбука не стирает ДЗ, написанное на телефоне;
- старый снимок в облаке не стирает свежее ДЗ на телефоне;
- импорт файла больше не заменяет всё целиком, а сливает.

## Облако

Один канал — Cloudflare Worker (`worker/worker.js`). Раньше их было три:
воркер, CrudCrud и зеркало на GitHub Pages. CrudCrud не отвечает и вдобавок
стирает данные через 24 часа, а в зеркало никто не писал — два канала из трёх
были мёртвыми.

Если оператор режет `workers.dev`, есть запасной путь: кнопка **«📤 Отправить
файлом»** кладёт `домашка.json` в любой мессенджер или прямо в **iCloud Drive**.

## Связь с ноутбуком

Синхронизатор `.github/scripts/sync.js` + задача в планировщике Windows.

Один раз запустить:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-sync.ps1
```

Дальше он сам каждые 5 минут забирает ДЗ в `дз/домашка.json` и заливает
готовые решения из `готовые/`. Остановить — `.\stop-sync.ps1`.

Команды вручную:

```bash
node .github/scripts/sync.js list   # что ждёт решения
node .github/scripts/sync.js pull   # забрать с телефона
node .github/scripts/sync.js push   # залить готовое
node .github/scripts/sync.js clean  # выкинуть мусор из облака
```

Готовое кладётся файлом `готовые/2026-09-29_12-20.txt` — дата и час начала
пары. Знак `|` в имени использовать нельзя: он зарезервирован в Windows,
и файл просто не создастся.

## Файлы к заданию: презентации, методички

У пары можно хранить файлы. Открываются тапом.

**От ассистента.** Кладёшь файл в папку `files/` с именем пары:

```
files/2026-09-30_14-10.pdf                  — один файл
files/2026-09-30_14-10_prezentaciya.pdf     — несколько файлов
```

Синхронизатор сам привяжет файл к паре и положит в задание ссылку. Файл
раздаётся с GitHub Pages, поэтому в облако попадает только ссылка и размер —
сам PDF никуда не копируется. **Папка латинская:** кириллица в URL ломает
ссылки на iPhone.

**С телефона.** В паре жмёшь «＋ Прикрепить файл с телефона» — файл уходит в
облако вместе с ДЗ по кнопке «⬆ В облако». Ограничение 2,5 МБ: такой файл
хранится прямо в записи, загрузить его на сервер некуда. Больше — присылай
ассистенту файлом.

Файл, который не удалось привязать, не теряется молча: синхронизатор пишет
в консоль, что именно пропустил и почему.

## Сверка расписания

Расписание сверялось с официальным источником
(`apeks.tksu.ru/api/call/schedule-schedule/student`, группа Б-ОРМ-41 = `group_id 665`)
и **расходилось с ним** — 8 пар по времени и предмету, 1 по кабинету, 4 по
преподавателю. Расписание обновлено по Апекс-ВУЗ, на 29.09 разница была
существенной: пара Практикума стояла на 10:25 вместо 17:40.

Названия предметов приведены к тем, что уже были в приложении: записи заданий
ключуются названием пары, и переименование предмета отправило бы их в «мусор».
Запись с исчезнувшей пары переносится на новую позицию того же предмета.

Сам источник отдаёт данные с битыми пробелами («Практикум  проектирования
культурно- массовой») и с повреждённым символом внутри слова, поэтому названия
нормализуются перед сопоставлением.

## Готовое решение и презентация

Готовое решение — текстом в `готовые/<дата>_<час-минуты>.txt`.
Презентация — файлом в `files/`. Оба подхватываются автоматически.

Связь с облаком бывает рваной (соединение обрывается, запрос подвисает),
поэтому синхронизатор делает три попытки с паузой. Без этого фоновая
синхронизация просто молча не отрабатывала.

## Напоминания о парах

Отправляет **воркер** (`worker/worker.js`) — у него таймер Cloudflare,
он срабатывает раз в минуту.

Почему не GitHub Actions, как было раньше: у Actions cron заявлено
«каждые 5 минут», а по факту он запускался **раз в 3–6 часов** (замерено
27–29.09.2026: 06:48, 01:04, 21:24, 15:51, 07:33, 01:36, 23:08, 20:20, 17:33,
12:58). Окно поиска пар было 25 минут, при таких пропусках напоминание
промахивалось мимо всегда — за всё время **не пришло ни одного
уведомления**. Документация GitHub подтверждает, что `schedule` задерживается
при высокой нагрузке.

`push-reminders.yml` и `send-reminders.js` оставлены как страховка, с широким
окном (195 минут) — если таймер воркера не отработает, cron подстрахует.

Напоминание приходит за 10–13 минут до пары, утром около 07:00 — списком на
день. `LEAD_MIN` — желаемый запас, `GRACE_MIN` — поправка на шаг таймера.

Push приходит **только** приложению, добавленному на Главный экран
(Safari → «Поделиться» → «На экран „Домой“») на iOS 16.4+. Из вкладки Safari
пуши не работают — это ограничение iOS.

### Развёртывание воркера

Исходник раньше жил только в панели Cloudflare, в репозитории его не было —
из-за этого воркер нельзя было ни починить, ни перенести. Теперь он здесь.

```bash
npm i -g wrangler
cd worker
wrangler kv namespace create DB
wrangler kv namespace create SUBS
wrangler kv namespace create VAPID_KV
wrangler kv namespace create SETTINGS_KV
# вставить полученные id в wrangler.toml
wrangler deploy
```

Пара ключей VAPID генерируется сама при первом срабатывании таймера и
складывается в KV. Приложение само берёт публичный ключ через `/api/vapid` —
зашивать его в код больше не нужно (раньше он был зашит и разошёлся с
ключом воркера, из-за чего уведомления не приходили, а диагностика показывала
«всё хорошо»).

## Структура

| Файл | Что это |
|---|---|
| `index.html` | приложение «Шарага» |
| `sw.js` | service worker: офлайн и приём push |
| `worker/worker.js` | облако: хранение, подписки, таймер напоминаний |
| `worker/wrangler.toml` | настройка развёртывания воркера |
| `.github/scripts/sync.js` | синхронизатор для ноутбука |
| `start-sync.ps1` / `stop-sync.ps1` | запуск и остановка фоновой синхронизации |
| `.github/workflows/push-reminders.yml` | страховка напоминаний через Actions |
| `дз/домашка.json` | что записано с телефона |
| `готовые/*.txt` | готовые решения, которые уедут в облако |
| `assets/` | логотип КГУ и иконки |

## Диагностика

Вкладка «Задания» → **🩺 Диагностика** → «Проверить всё». Показывает, запущено
ли приложение с Главного экрана, есть ли разрешение, жива ли push-подписка и
совпадает ли её ключ с серверным, какие задания ждут решения в облаке.
Кнопка «📋 Скопировать отчёт» — чтобы прислать результат ассистенту.

## Известные ограничения

- iPhone не даёт приложению работать в фоне: данные из облака тянутся при
  открытии и возврате на экран. Уведомления приходят, даже когда приложение
  закрыто, — это отдельный механизм (push).
- Лекция и практикум одного предмета в один день (например, «Социология»
  28.09 в 15:55 и 17:40) — это разные пары, поэтому задание с лекции получает
  срок на практикуме в тот же день. Если нужен другой срок, поправь
  `dueD`/`dueT` в `дз/домашка.json`.
- GitHub отключает cron в репозитории, где 60 дней не было активности.
- Расписание в `index.html` и в `worker/worker.js` должно совпадать: это два
  файла с одними и теми же 65 парами, и при расхождении напоминания будут
  приходить не о тех парах.
